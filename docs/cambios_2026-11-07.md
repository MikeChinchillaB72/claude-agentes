# Cambios del 2026-11-07

## Qué se hizo

Miguel pidió crear los plugins con los documentos que se deberían haber levantado, las
instrucciones para instalarlos en Salesforce y en monday.com, y todo lo que el cliente debe
saber. Eligió **seis plugins que funcionan con las dos plataformas** (decisión del 2026-11-06)
y dio el «hazlo» al plan.

1. **Catálogo** [`.claude-plugin/marketplace.json`](../.claude-plugin/marketplace.json), llamado
   `agentes-crm`, con los seis plugins en `plugins/`:
   - Ventas (Sales Cloud o monday CRM): `ventas-seguimiento`, `ventas-calificacion-leads`,
     `ventas-analisis-pipeline`.
   - Servicio (Service Cloud o monday service): `servicio-atencion-contexto`,
     `servicio-clasificacion-casos`, `servicio-respuestas-conocimiento`.
2. **Cada plugin** trae su manifiesto, un `.mcp.json` con los conectores `salesforce` y `monday`,
   una skill con sus criterios de negocio aparte (`references/criterios.md`), un README y siete
   documentos en `docs/`: requisitos, seguridad y datos, instalación en Salesforce, instalación en
   monday.com, guía de uso, pruebas de aceptación y preguntas frecuentes.
3. **Guía del cliente** en [cliente/](cliente/README.md): instalar en Claude, preparar Salesforce,
   preparar monday.com, seguridad, y costos y soporte. Los documentos de cada plugin la enlazan
   en vez de repetirla.
4. Se actualizaron [CONFIGURACION.md](CONFIGURACION.md) (sección Plugins), [README.md](README.md),
   el README raíz, CLAUDE.md y [pendientes.md](pendientes.md) (P1 concretado; P5 ampliado;
   P6 a P9 nuevos).

Los seis documentos de cada plugin se generaron con un script de un solo uso, fuera del
repositorio, a partir de una tabla con lo propio de cada plugin. Desde ahora se mantienen a mano.

## Decisiones técnicas y sus fuentes (M2)

Consultadas el 2026-11-06 y el 2026-11-07.

| Decisión | Por qué | Fuente |
|---|---|---|
| Un plugin con dos conectores, uno por plataforma | Cada empresa conecta solo el suyo; el otro queda sin conectar. Evita duplicar doce plugins | [Plugin structure](https://claude.com/docs/plugins/build): un `.mcp.json` remoto aparece en la pestaña Connectors del plugin |
| **Solo lectura**, impuesta por permisos | Mínimo privilegio y «el código decide, el modelo propone» del documento de casos de uso. Salesforce `sobject-reads` es «read and query only, no mutations». En monday.com el token no puede superar los *scopes* de la app | [Standard MCP Servers Reference](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/servers-reference.html), [Control MCP access with an OAuth app](https://developer.monday.com/api-reference/docs/control-mcp-access-with-oauth-app) |
| App OAuth propia de monday.com en vez del conector genérico | El servidor alojado no documenta un modo de solo lectura y tiene herramientas que escriben (`create_item`, `delete_item`...) | [mondaycom/mcp](https://github.com/mondaycom/mcp), [OAuth scopes](https://developer.monday.com/apps/docs/oauth#set-up-permission-scopes) |
| Servidores alojados por cada plataforma, sin servidor propio | Sin infraestructura; respetan los permisos de cada usuario | Mismas fuentes |
| Solo skills y conectores; sin hooks, agentes ni `bin/` | Las skills y los conectores remotos cargan en claude.ai, Cowork y Claude Code. Hooks y agentes no cargan en claude.ai, y `bin/` impide instalar en claude.ai y Cowork | [Plugin structure](https://claude.com/docs/plugins/build) |
| Criterios de negocio en `references/criterios.md` | Regla M7: se cambian sin tocar las instrucciones. El plugin no puede leer `config/` del repositorio | [Plugin structure](https://claude.com/docs/plugins/build) (archivos de apoyo de una skill) |
| Línea de instalación en cada README | Recomendación de `claude plugin validate` (Claude Code 2.1.319) | — |
| Versión 0.1.0 | No está probada en plataforma real (T5); pasa a 1.0.0 al superar sus pruebas | — |

## Comprobaciones

- `claude plugin validate .` (catálogo) y en cada plugin: **pasa** (Claude Code 2.1.319).
- `python -m redes` y `pytest`: en verde.

## Qué está sin comprobar

Todo lo que depende de una plataforma real (P5): que los conectores autentiquen, que las
consultas de ejemplo de las skills funcionen con el servidor `sobject-reads`, la base de
conocimiento de monday service y los registros de auditoría. Los costos de Salesforce vienen de
un artículo de un tercero ([Stacksync](https://www.stacksync.com/blog/salesforce-mcp-server-endpoints-tools))
y se marcan para confirmar con el proveedor (P9).
